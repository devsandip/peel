# Current identity for existing-run inspection

[Issue 62](https://github.com/devsandip/peel/issues/62) is the credential prerequisite split from issue 61 before opening a broad collector PR, under [M2.2](https://github.com/devsandip/peel/milestone/2), SPEC FR-04/14/20 and AC-04/12/13 prerequisites. The existing [new-run identity collector](cloud-identity-observations.md) requires two hours of authorization/session runway. Keep that requirement for new resources. Existing-run metadata/cleanup inspection needs current authenticated identity without a new-run lease, quote or authorization cutoff.

Require an explicit existing profile, independent expected account and us-east-1. Reuse the existing fixed configuration/STS argument builder and environment safeguards. Read disabled/absent CLI history first, then configured SSO account/role and unsupported credential-process/nested-role/web-identity settings before authentication. Compare configured account with the explicit pin; STS never supplies the expected account. Match regional STS account and configured AWSReservedSSO role. Return only a frozen matched identity/configured role, never raw session ARN or credential fields.

There is no credential export, expiry/refresh assertion or provisioning/ownership flag. An expired run does not prevent this operation; a current authenticated STS response establishes only identity at observation time. Metadata callers must invoke the same gate before and after their reads and reject account/profile/role changes. Existing new-run checks remain unchanged and mandatory before a create.

Bound individual subprocesses to 15 seconds/64 KiB and the operation to 45 seconds. Capture data properties before awaits. Support an external abort signal, reject late readers after timeout/cancellation and remove signal listeners/timers after completion. Fixed errors contain no raw cause or rejected values. Keep TLS, pinned regional endpoints, disabled retries/history and no shell/debug/pager/prompt. Do not read or change credential caches manually.

Use synthetic injected readers to cover account/role/history/unsupported-flow safeguards, input mutation, malformed/private output, deadlines, cancellation, clock changes and immutable results. Verify actual Node 24 plus shared tests, TypeScript, formatting, web build and all hosted gates. No live account/audit probe, actual operator ledger, AWS resource writes or real note/default database belongs here. Issue 61 follows separately; audit 51 and managed acceptance 30/31 remain open. App Cloud and canonical v0.7 are unchanged.

Nine focused cases pass under actual Node 24.22.1 and the development runtime; all 262 shared cases, TypeScript, formatting and web build pass locally. Optional missing settings accept only exit 1 with empty stdout/stderr and no kill/signal. All other failures remain unknown. Hosted gates follow before integration; fixture evidence is not a real account or cleanup observation.

Direct Node 24 import is also checked without a transpiler. That check caught a TypeScript parameter property that Vitest's transform accepted; the error class now uses erasable declarations. Add the direct import to hosted Node 24 coverage so a passing transformed test cannot mask operator-runtime incompatibility.
