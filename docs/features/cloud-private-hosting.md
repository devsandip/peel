# Private development Lambda hosting

## Requirement and PR boundary

[Issue 29](https://github.com/devsandip/peel/issues/29), in [M2.2](https://github.com/devsandip/peel/milestone/2), connects the [packaged handler](cloud-lambda-artifact.md) and [data/identity template](cloud-data-identity.md). SPEC FR-04/14/20 and AC-04/12/13 remain product requirements. One purpose: define the private function, its exact data permissions, stable key and artifact dependencies. This PR creates no resource and enables no app feature.

Independent expiry/deletion/sentinel infrastructure is [issue 36](https://github.com/devsandip/peel/issues/36), split before implementation to keep its permission graph separately reviewable. Both definitions must merge before issue 30's deployment tooling can apply anything; issue 31 still requires actual cleanup rehearsal and verified managed evidence. A rendered hosting template alone is not a safe deployment plan.

## Plan before implementation

1. Render a private encrypted artifact-bucket bootstrap separately from the main stack. Block public access, enforce bucket ownership and TLS, disable versioning/retention and supply a short code-only lifecycle backstop. The later runner must create this owned bootstrap, upload/verify the exact ZIP, then create the function; putting the bucket and its not-yet-uploaded code in the same creation graph would race.
2. Compose the existing six data/identity resources with a named private Node 24 x86 Lambda, one exact-table execution role and an owned Secrets Manager secret. Bound memory to 256 MiB, function time to 30 seconds, temporary space to 512 MiB and reserved concurrency to one. The later preflight must verify available reservation quota; do not alter account quotas to bypass a failure. No URL, API, event source, VPC/NAT, provisioned concurrency, active tracing, log-write policy, general storage/admin permission or public invocation grant.
3. Accept only canonical run identity, lowercase ZIP SHA256/size and canonical bounded start/expiry values. These pure factories do not consult AWS, credentials or the current clock. The later guard checks actual freshness, authorization cutoff, account/region and current pricing. The function's fixed environment lease is enforced by the existing runtime, including warm expiry.
4. Keep the existing 32-byte/base64 cursor-key contract. A later runner generates it privately in memory, supplies a required NoEcho/no-default CFN parameter to SecretString, and uses a dynamic reference in function environment. The parameter is not an identifier, output or metadata value. No fixture key/default, raw error, secret command argument, value checkpoint or key rotation claim. The function role does not need permission to retrieve the secret; CFN resolves it using the authorized deployment context.
5. Check provider schemas for bootstrap and main templates. Test strict artifact/lease/run inputs; exact code/key/runtime wiring; absence of public or logging privileges; the exact table read/transaction-write permissions; and configuration flowing into the real parser. Use injected synthetic intrinsic results only. No real key/provider request or default user database. Run type/format/shared/artifact/schema/web validation and all hosted gates before a focused local no-reply merge.

## Primary-source basis

[AWS transaction IAM guidance](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/transaction-apis-iam.html) maps transaction operations to per-item permissions; SDK Transact method names are not the policy action list. [Lambda's CFN definition](https://docs.aws.amazon.com/AWSCloudFormation/latest/TemplateReference/aws-resource-lambda-function.html) specifies package/role/runtime/reservation configuration. AWS documents the [S3 TLS service-principal exception](https://docs.aws.amazon.com/AmazonS3/latest/userguide/amazon-s3-policy-keys.html) used in a Deny policy; it grants no public access.

[NoEcho](https://docs.aws.amazon.com/AWSCloudFormation/latest/UserGuide/parameters-section-structure.html) masks stack descriptions/events, with explicit exceptions for metadata, outputs and identifiers; none may contain this key. [CFN CloudTrail records parameter names, not values](https://docs.aws.amazon.com/AWSCloudFormation/latest/UserGuide/cfn-api-logging-cloudtrail.html). [Secrets Manager](https://docs.aws.amazon.com/secretsmanager/latest/apireference/API_CreateSecret.html) excludes SecretString/SecretBinary from sensitive request logging. [Dynamic reference documentation](https://docs.aws.amazon.com/AWSCloudFormation/latest/UserGuide/dynamic-references-secretsmanager.html) explains resolution and why changing the stored secret alone does not refresh an existing function environment. Production rotation remains open.

## Evidence and remaining gates

Four focused shared cases pass: malformed/oversized artifacts and invalid leases are rejected without coercing input objects; the private encrypted bootstrap is separate from the function creation graph; runtime permissions are restricted to exact-table reads and the service's transaction-only Put/Delete/ConditionCheck operations; and the secret reference/fixed environment lease feed the actual runtime parser. No standalone write, Scan, log-write, secret-fetch or admin permission is granted to the function.

The actual package manifest drives the renderer, renamed to scripts/render-cloud-iac.mjs as it now emits three templates. Pinned cfn-lint validates all three against us-east-1 provider schemas without warning/error output. All 146 shared cases in 30 files, TypeScript, source/script formatting, existing Node 24 packaged checks and web build pass locally. The browser size warning remains and the Lambda ZIP remains unchanged at 336,713 bytes / SHA256 8603e9d37675877161f68d7e5a3b97b8cc57e247302a7dcbf690600671eb1013. CI now builds the artifact before rendering its hosting references; hosted results are recorded in the linked PR/issue when complete.

With Node 24, run `pnpm cloud:build`, `pnpm cloud:iac:render`, `pnpm cloud:iac:check` and `pnpm cloud:check`. No secret value is generated by rendering or included in its output. Schema/policy/configuration checks do not simulate actual IAM, secret resolution or available reservation quota. This is development IaC, not real reservation/identity/IAM, key persistence, active lease/deletion, API Gateway, native/web login, live sync or app acceptance. Deployment still requires the independently reviewed cleanup graph, guarded tooling, verified account/region/cost budget and actual rehearsal. Version 0.7 scope/mockups remain unchanged.
