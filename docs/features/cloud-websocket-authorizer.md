## Trust and lifecycle limits

[AWS's WebSocket authorizer](https://docs.aws.amazon.com/apigateway/latest/developerguide/apigateway-websocket-api-lambda-auth.html) is a connection-time hook. Its [policy output](https://docs.aws.amazon.com/apigateway/latest/developerguide/api-gateway-lambda-authorizer-output.html) uses principal/policy and scalar context; the resource length cap informs this adapter's config bound. [Subprotocol selection](https://docs.aws.amazon.com/apigateway/latest/developerguide/websocket-connect-route-subprotocol.html) is a separate integration response. Matching metadata is a configuration check, not attestation of invocation provenance. Actual deployment must restrict invocation to the reviewed Gateway source and review origin/proxy/cookie/TLS/logging, decision caching and time budgets before enabling it.

A returned policy is only a point-in-time admission prerequisite. Ticket deadline is the deadline to register this attempt, not an ongoing connection lease. A later registry must compare the original connection ID and recheck current session/entitlement/library before attaching and during fan-out/revocation. No actual socket, negotiation, registry, publication, hosted ticket store, native bearer flow or continuing authorization is implemented here. Keep those as later plan lines, not a speculative issue tree.
