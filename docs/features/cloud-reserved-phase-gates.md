# Current phase and provenance gates for a reserved run

[Issue 131](https://github.com/devsandip/peel/issues/131) is one design refinement under issue 30 / [M2.2](https://github.com/devsandip/peel/milestone/2), following PR 130. It supports [SPEC](../SPEC.md) FR-04/14/20 and AC-04/12/13 prerequisites. Read the [creation-journal protocol](cloud-creation-journal.md), [local session lineage](cloud-preparation-session.md), [deployment policy](cloud-deployment-guards.md), [hosting](cloud-dev-hosting.md) and [independent cleanup](cloud-dev-cleanup.md). This feature plan precedes the canonical protocol changes. It implements no runtime, collector, SDK, key/token, storage or provider behavior. Functional v0.7 remains unchanged.

## Purpose

The private session establishes local acknowledgement lineage. The actual reservation is already consumed and never becomes a new budget slot. Current gates must retain the original context/recipe/plan/quote/request identity, actual selected ledger and original absolute lease. Reading a row, re-opening sources, self-consistent metadata or a caller flag supplies neither lineage nor current provider approval. Never replay new-run validation with a fabricated empty ledger.

## Evidence chain

Keep distinct: captured original integrity, actual local source synchronization, fresh reserve/bootstrap ACK lineage, actual current collector provenance, phase-specific provider ownership/settlement and the later one-use send capability. A pure eligibility result remains unproven. A future trusted coordinator must itself call reviewed actual collectors with independently retained profile/account/region and protected configuration, preserve the oldest critical observation time and hold any readiness capability privately. Caller-provided collector dependencies, response DTOs or booleans are fixture inputs, never current approval. The current real audit/managed gates remain stopped/not-ready; this draft does not run or override them.

Before every preparation/fence, revalidate actual active reservation/scope and separately acknowledge the unchanged original source stores again. A safe session read is not that synchronization acknowledgement. Revalidate current identity/session/credential cleanup runway, original authorization and absolute phase times, exact source/main/latest required CI/clean tree, original current cost evidence, capacity, hooks/audit coverage and the complete phase-appropriate target inventory. Unknown, partial, denied, truncated, changed, expired or stale facts stop new creation. Do not turn any existing unproven collision/metadata adapter into full absence/ownership proof by relabeling it. No generic observed/verified flag or opaque proof hash substitutes for retained bounded facts and their provenance. Later proof adapters must keep the creation journal's whitelisted identifier/status/count/configuration-fact projections and limits; no raw responses, event properties, parameter values, secret values or unrestricted reasons are retained.

Original quote evidence is bound by the original normalized plan hash. The live session retains its initial raw quote DTO privately, which proves no official-source provenance by itself. A trusted aggregator must independently retain actual collector provenance or obtain a fresh official observation. Keep the original quote/plan unchanged; a distinct current assessment may bind a fresh quote/provenance and compare its full reviewed regional rates/units/source facts with the original evidence. A different retrieval timestamp is not permission to overwrite the original quote digest. Default to refusing unresolved origin, expired original evidence or substantive rate/source drift and preserving cleanup; any more permissive drift policy needs separate review. The old overnight cutoff/allowance is expired and cannot authorize an actual run. Cleanup does not require a new-run quote or new reservation.

| Before first guard       | Complete exact-name target absence and no conflicting original stack/resource state; no prior intent/fence to replay; actual current gates above                                                                                                                | No preparation or send; preserve consumed reservation and workspace                                                             |
| Before sentinel          | Independently correlate and settle the original guard operation; exact owned roles/group/schedules, trust/target/expiry/token readback; sentinel and other not-yet-created resources absent                                                                     | Stop creation and use independently proven-owned cleanup                                                                        |
| Before artifact stack    | Guard and empty sentinel ready and both original schedules read back by start+10minutes; expected created resources proven owned; artifact/data targets absent                                                                                                  | No artifact provisioning merely to gain time or repair readiness                                                                |

| Before data              | Actual scheduled sentinel deletion correlated to original schedule/target/role/token; sentinel stack/table settlement and complete absence verified; original data schedule still armed; original artifact object proven/verified and current runway sufficient | No manual deletion as rehearsal, no replacement key/request or extended lease                                                   |
| Before managed smoke     | Original data/identity/function operation and exact resource inventory independently owned/settled; required runtime/cleanup checks, bounded invocation/user protocol and original stopTestsAt enforced                                                         | No app activation, arbitrary invocation or second attempt                                                                       |

Global targetNames=absent is a first-guard/new-run condition. It is wrong for later phases because the expected owned guard/sentinel/artifact resources now exist. Later gates require exact phase-specific inventory and operation/ownership/settlement proofs, with all not-yet-created resources independently absent. Names, tags, a returned stack ID, empty description, single not-found or manual verified flag are insufficient.

## Time and failure

The original 15-minute plan age and start-at-most-30-seconds-old checks apply to the fresh reservation. Do not replay them after reserve against a fabricated prior, or renew them by changing original timestamps. In particular, legitimate data preparation follows the start-plus-15-minute sentinel rehearsal. Later forward progress uses the original absolute phase deadlines, unchanged recognized reservation and fresh current evidence. Critical observations remain at most two minutes old, using the oldest actual observation with no future tolerance; the original funding quote remains within its 24-hour age limit. A separate fresh quote assessment cannot renew the original quote's age. Current time cannot precede the original reservation or move backward across a checked boundary.

The existing five-minute CreateStack timeout is a request policy, not a guaranteed bound on provider settlement/rollback or cleanup. It does not establish start+10minute guard/sentinel readiness. A future gate/runner must define conservative local operation/wait budgets, check current remaining runway before each action and enforce the original readiness/test-stop/expiry/cleanup cutoffs. If it cannot establish adequate runway, do not provision. A missed cutoff aborts new creation and enters owned cleanup; no rescheduling/restamping or allowance increase. Actual provider timing remains managed evidence, not an offline policy claim.

Before preparation, a short-lived private current assessment binds the original run/kind, original source/genesis, actual journal revision and validated phase evidence. It cannot bind a request digest that does not exist yet. Only the same live coordinator may use it in the winning preparation transaction; that transaction captures the token, safe request projection and full unsigned digest together. After successful preparation acknowledgement, bind the resulting exact immutable tuple and active material to private state. Immediately before fencing/send, obtain or refresh the required actual current evidence and bind the recheck to that captured kind/token/request digest and current journal revision. Recheck time, current identity/source and required dependencies. Neither assessment runs network IO inside the journal transaction. These private assessments must not survive process loss, copy/JSON, another run, conflicting request, changed source/ledger, failed source sync or uncertain commit. Local validation/fence errors invalidate the coordinator for further creation. No database transaction spans network IO.

Cleanup retains a separate current-identity/permission/independent-ownership route. Expired source/quote/lease cannot block otherwise authorized proven-owned deletion, but cannot excuse lost provenance. Missing permission/ownership remains unresolved, with original state preserved and no new run. Local disk failure cannot authorize creation or a false durable teardown/funding receipt. Guard/artifact bootstrap residue remains a real cleanup gap after runner loss; do not describe schedules as self-cleanup of those resources.

## Implementation boundaries after a reviewed protocol

A pure initial-guard eligibility contract could be the first implementation slice: accept exact original data, actual-reservation observations and current fact DTOs, reject stale/drifted data, return only unproven normalized assessment. It must not mint permission from caller strings. Actual private collector aggregation/provenance, later phase ownership/settlement, trusted preparation, dispatch/wire transport and complete cleanup are separate meaningful slices with their own issues, tests and gates. Keep them disabled/unreferenced until their actual prerequisites exist. No speculative later issue backlog.
