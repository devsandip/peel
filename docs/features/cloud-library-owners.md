## One delivery purpose

Add a parent controller for one browser workspace and one captured store, validated frozen scope, mutation sender and account signal. Its open/create/Put-away functions implement the existing workspace callback shapes; metadata-only snapshot/subscription updates the parent's catalog refresh key. Create is synchronous and does no I/O. Reject foreign stores/scopes/note identifiers/owners/sessions before access; no later global account lookup. Authentication, download/reconnect/live orchestration and normal-app activation remain separate.

Keep one upload owner per note. Coalesce overlapping opens of the same note, suppress superseded cache reads before returning a candidate, and explicitly reopen a closed retained owner without replacing its pending operation or pause state. Opening another note or creating a capture supersedes older outstanding selection requests. Retain original-context pending and copyable recovery even after account abort. The parent continues to own storage lifetime and recovery across authentication changes.

Put-away acknowledgement is idempotent for the exact owner and closed session. Release only acknowledged closed, retained, error-free sessions after server-confirmed Saved, or a scoped read proves an untouched capture has no row. Empty text alone cannot prove an untouched capture. Never release during reopening or before the parent close callback. Abort each owner's derived signal before forgetting it, including after confirmation: idle publication can precede the uploader's final queued timer, so merely deleting an idle map entry permits competing actors. Failed absence inspection conservatively retains the owner; there is no automatic storage retry loop. Canceled contexts keep retained recovery reachable, do not close storage and cannot create/open new owners.
