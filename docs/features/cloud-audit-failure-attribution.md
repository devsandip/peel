# Safe attribution for unavailable Cloud audit collection

[Issue216](https://github.com/devsandip/peel/issues/216), under issue51/[M2.2](https://github.com/devsandip/peel/milestone/2), supports [SPEC](../SPEC.md) FR-04/14/20 and AC-04/12/13 prerequisites. Read [audit observation](cloud-audit-observations.md). This plan precedes implementation.

Add fixed stage and validated public-region context to unavailable outcomes from the existing collector. Bind concurrent failures to their own operation, and leave region null when global timeout/abort cannot identify one. Return no raw provider errors, metadata, identifiers or caller-supplied private strings. If needed, expose a frozen copy of the reviewed public region list from audit-regions.ts only to whitelist diagnostic names; existing registry parsing/output/ordering stays unchanged.

Successful observed output, classifiers, identity/cutoff/credential requirements, all-region coverage, ordering/concurrency, pagination/readiness policy remain unchanged. These diagnostics cannot prove historical cause, disabled opt-in status, account policy or audit absence. No new command, live provider/profile/config/private-data read, stopped retry, permissions or app change.

Existing module/unit tests plus this plan are owned, with only the bounded public-list export allowed in audit-regions.ts. Synthetic tests cover first/later concurrent failure attribution, earlier/final stages, abort/deadline, unknown region redaction, privacy/immutability and unchanged success/readiness. Root executes Git/tests after the file-edit worker exits because agy shell is denied; no settings are broadened. PinNode24 focused/static/shared and source/mainall3 plus review precede acceptance. Parent51 remains unresolved until actual evidence exists.

## Implementation contract and verification status

- `infra/cloud/audit-regions.ts` exports `cloudAuditCommercialRegions`, a frozen shallow copy of the reviewed 28 public commercial region names (`Object.freeze([...commercial])`), leaving `parseCloudAuditRegions` and `collectCloudAuditRegions` unchanged.
- `infra/cloud/audit-observations.ts` exports `CloudAuditFailureStage` (`"registry" | "identity" | "organization" | "hooks" | "trails" | "lake" | "caller-identity"`) and adds `stage: CloudAuditFailureStage | null` and `region: string | null` to frozen `kind: "unavailable"` results while keeping `kind: "observed"` byte-shape identical.
- Each command execution and response/count validation binds its own immutable `AuditFailure` context (`stage` and `region` whitelisted against `cloudAuditCommercialRegions`, falling back to `null` for unknown or caller-injected strings) without shared mutable per-region state across concurrent 4-region Lake batches.
- Pre- and post-stage checks (`invalid-input`, `clock-invalid`, `unsupported-environment`) report `stage: null, region: null`; `registry` reports `stage: "registry", region: null`; `us-east-1`-scoped stages (`identity`, `organization`, `hooks`, `trails`, `caller-identity`) report `region: "us-east-1"`; global 90-second deadlines and `AbortSignal` cancellations report `region: null`.
- `tests/unit/cloud-audit-observations.test.ts` covers first-batch and later-batch concurrent Lake failures completing out of order, malformed JSON and `count()` failures across stages, prerequisite/environment/clock failures, global deadlines and shared aborts, spoofed/GovCloud/private region redaction, frozen output privacy, and unchanged 28-region `kind: "observed"` output.
- Verification status from the file-edit worker: static file audit only (`0` shell/test/provider commands run). Actual Node 24/development Node Vitest execution, `tsc --noEmit`, Prettier, `gitleaks`, Git commit/push, hosted CI (`web-and-core`, `cloud-artifact`, `native`) and review remain pending Root execution.
