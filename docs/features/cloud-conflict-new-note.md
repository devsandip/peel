## Bounded retry and uncertain writes

Keep the allocated ID and intended metadata for an active source/generation attempt. Double clicks/concurrent calls must not allocate two copies; busy/coalesced bounded outcomes are fine. An uncertain commit must not blindly allocate another ID on explicit retry. Re-read/validate a matching retained destination before reusing it, respecting the existing durable-store contract. Never overwrite a later edit, silently rotate an uncertain ID or delete a possibly retained copy. Definite invalid/old/colliding allocator outputs are refused without overwriting existing data or automatic allocation loops. Keep only needed intent metadata, not unbounded raw-body history.

No recovery runs automatically on constructor/startup/reload. No cross-restart exactly-once promise is invented without durable lineage: already-retained copies remain in the original account library, and a fresh explicit decision can be a distinct copy. The original recovery draft is kept until a separate explicit discard/observed-purge acceptance, never cleared merely because a new copy was retained. The later UI must explain new Active copy versus original deletion and ordinary Pending/ACK behavior.
