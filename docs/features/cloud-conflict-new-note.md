## Implementation notes and worker verification status

CloudConflictNewNoteRecovery is implemented in apps/web/src/cloud-conflict-new-note.ts against the frozen constructor and prepare(sourceNoteId, expectedGeneration) result contract with zero contract renames or incompatibilities. Construction captures own-data store and scope descriptors without invoking getters, freezes the validated scope, binds original store.read and store.commit references, wraps crypto.randomUUID safely as () => crypto.randomUUID(), and performs zero storage or network operations. No sender is accepted or invoked, and caller stores are never closed.

Inside the shared per-note gate and a per-note in-progress set, prepare validates note ID and safe positive integer generation before gate entry, reads scoped durable source state, checks exact generation through ensureExpectedGeneration, and requires an actual conflict with remote === null, positive safe-integer remoteRevision and a local upsert snapshot. Missing, non-conflict, non-purged and local-purge rows return not-recoverable before retirement or ID allocation so any queued closed owner on a non-recoverable note stays intact. Once recoverable source state is proven, lease.retire() runs once (rechecking quiescence if the closed owner began work during validation), and only snapshot.bodyMarkdown is copied into a fresh Active draft (schemaVersion 1, fresh createdAt/updatedAt, null deletedAt/purgeAfter, no copied origin or serverRevision) committed under expected-null CAS via createCloudClient, saveCloudDraft and cloudStateWrite. Because the new row is durably committed at generation 1 with pending and current set, an explicitly recovered empty string draft opens with capture: false in untouched CloudDraftSession and survives open, putAway and later upload without reviving the purged source identity, while the original source row bytes remain untouched.

Immediately after the destination null read and before marking commitStarted or invoking store.commit, guardSourceBeforeCommit re-reads the source row and checks ensureExpectedGeneration, recoverable purged-conflict state and signal activity so a source generation advance during a held destination read refuses stale with zero destination commits (supporting Root's stale/source-generation guard omission control on ensureExpectedGeneration or guardSourceBeforeCommit). Bounded per-source RecoveryAttempt metadata records only expectedGeneration, newNoteId, createdAt, updatedAt, bodyBytes and commitStarted without retaining bodyMarkdown strings. Pre-commit destination collisions refuse unavailable without overwriting or looping, pre-commit read/commit exceptions reuse the allocated ID on explicit retry, and post-commit uncertainty re-reads and validates exact stateJSON equality before reusing the retained ID with zero extra writes while refusing to overwrite later destination edits or rotate an uncertain ID.

Unit tests in tests/unit/cloud-conflict-new-note.test.ts target owners.newNoteRecovery() across fresh synthetic SQLiteCloudStateStore and SQLiteCloudServerStore fixtures (plus bounded allocator, gate and constructor doubles for negative invariants). Coupled apps/web/src/cloud-library-owners.ts remains untouched for Root's post-exit factory and shared closed-note gate integration. All shell, Git, TypeScript, Prettier, Vitest and browser verification checks are UNRUN by the file-only worker and remain pending Root's locked verification pass.
