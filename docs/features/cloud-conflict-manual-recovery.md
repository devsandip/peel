## Implementation notes

- **Original-identity unavailable boundary vs. invalid/aborted/replaced bindings** (`apps/web/src/cloud-conflict-resolution-panel.tsx`):
  - Separated broken/invalid owner bindings (`bindingInvalid` / `!controllerBinding`) and signal aborts (`isAborted`) from runtime `read` / `resolve` / `retry` `"unavailable"` outcomes on a still-valid, non-aborted original `CapturedPanelIdentity`.
  - Initial malformed/foreign/getter/pre-aborted props, dynamic account/store/scope/owners/signal/`noteId` replacement (`hasSamePanelIdentity`), and in-place `AbortSignal` aborts render `UnavailableResolutionPanel` (or unmount/replace `SelectedResolutionPanel` by `serial`), immediately hiding all note and manual text, clearing in-flight copy slots, advancing `readSerialRef`, suppressing late held read/clipboard completions, and never closing caller-owned stores.
  - On a runtime read/commit/resolve failure while the original identity remains valid and non-aborted, `enterUnavailable` sets `unavailable` (`unavailableRef.current = true`), clears `view`, `proposal`, `outcome`, and `adoptedRevision` without claiming persistence or rollback or leaking raw error text, suppresses background `ownerTick` / `refreshKey` auto-reads while unavailable, and renders the explicit `Retry loading conflict` button plus (when `combineDraft.dirty` is `true`, including empty `""`) the readonly `Preserved manual combined text` textarea and `Copy combined text` button using the existing guarded clipboard lifecycle.
  - `Retry loading conflict` (`handleRetryLoad`) performs strictly one `controller.read` on the bound original controller (`unavailable` is excluded from the background `useEffect` dependency list so recovery does not double-read). Repeated failure preserves the unavailable manual-recovery view without auto-retry; success restores `nextView` and user-entered `combineDraft` while keeping `proposal` cleared so a fresh explicit choice and generation confirmation are required.
