## One purpose and trust boundary

Implement `checkCloudInitialGuardFacts` in `infra/cloud/initial-guard-facts.ts`. It checks supplied original and current data for the initial guard only. It never obtains actual facts, reserves a slot, synchronizes a source, creates a private session/assessment or authorizes preparation/dispatch. No RNG/key/token, filesystem/SQL/network, current name/template factory, new-run validator, default clock or callback. Explicit integer clock input is data, not authenticated wall time.

A later trusted coordinator must itself obtain actual protected ledger/source observations and collector provenance, the genuine live session, actual current journal revision/intent state and adequate phase budgets/runway before preparation. The pure result supplies none of those capabilities. Existing journal genesis revision zero does not prove no pending intent or unsent operation. The checker does not read current journal rows or infer absence from a restored view.
