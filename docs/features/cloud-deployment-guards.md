# Controlled Cloud deployment-plan guards

## Purpose and PR boundary

[Issue 39](https://github.com/devsandip/peel/issues/39) separates pure plan validation from [issue 30](https://github.com/devsandip/peel/issues/30)'s actual lifecycle tooling. It implements prerequisites for SPEC FR-04/14/20 and AC-04/12/13 under the [hosting](cloud-dev-hosting.md) and [cleanup](cloud-dev-cleanup.md) plans. No AWS/Git/file operation, apply command or app Cloud capability belongs in this PR. Public v0.7 scope and mockups remain unchanged.

Follow with a separately tracked read-only preflight adapter, then owned-resource lifecycle/recovery and explicit apply/cleanup orchestration. Split those again if their review or rollback purposes diverge. Issue 30 stays open until its complete tooling criteria have evidence; issue 31 owns actual managed-service proof.

## Trust and input contract

The validator receives four separate data objects plus an explicit clock: a prepared plan, the operator's existing authorization/pinned identity, fresh preflight observations and the private consumed-run ledger. The read-only adapter must obtain the expected account/profile from existing trusted configuration or a previously verified private pin. It must never populate that expected identity from the STS result being compared. Validation cannot establish the provenance of caller-supplied observations; collecting and verifying them is the next PR's responsibility.

Accept only exact, plain data records, bounded arrays, primitive values and canonical timestamps/digests. Reject extra fields at every level, including token/password/note/key fields, symbols, accessors and custom prototypes. Errors have one fixed private message without the rejected value/cause. Return an immutable normalized snapshot, not mutable references to input objects. Actual account addresses and observations remain private and never enter public reports.

- Identity is one explicit existing profile, a 12-digit expected account and `us-east-1`; plan and observed identities must both match the independent authorization. Its explicit cutoff has no default.
- Bind source commit/tree, lockfile, ZIP bytes/SHA256 and the digest of the complete rendered template set. Observed source must exactly match the plan, clean worktree, current main and the exact successful CI commit. Require all three existing hosted jobs. A hash/string in this contract is not evidence that the collector performed the underlying operation.
- Plans last at most 15 minutes; critical observations last at most two minutes. No future timestamp/clock tolerance. The preflight collector must use the oldest critical observation time, not stamp stale data as fresh at the end.
- A new run uses a canonical UUID and a fixed 90-minute whole-second lease. Validate immediately before its first create/reservation: start is at most 30 seconds old and never in the future. This anchors expiry conservatively before the AWS write rather than extending it after slow setup. Return test-stop at expiry minus 30 minutes and cleanup-by at expiry plus 30 minutes; both the explicit authorization and usable credentials must cover cleanup-by. Cleanup/recovery itself must not call this new-run validator, since expired source/lease/budget must never prevent deletion of proven-owned resources.
- Preserve the [Lambda unreserved pool's final 100 units](https://docs.aws.amazon.com/lambda/latest/dg/configuration-concurrency.html): the observed regional unreserved quota must be at least 101 before reserving one. Collect it from [GetAccountSettings](https://docs.aws.amazon.com/lambda/latest/api/API_GetAccountSettings.html). Require observed absence of target-name collisions, CloudFormation hooks and data-event logging covering the experiment's target resources; unknown/unsafe observations refuse a new run without changing account settings.
- Require a current unexpired credential session. A shorter session can cover the run only when refresh is actually proven and its verified runway reaches cleanup-by. [Refreshable and legacy SSO configurations differ](https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-sso.html). No raw credential/token is accepted; the future adapter must prove refreshability rather than infer it from a profile label or claim that a single short STS session lasts two hours.

## Cost and run ledger

Compute the canonical hosting plan's conservative workload forecast from all 12 positive finite marginal regional rates, USD currency, retrieval time and a digest of the official source observations. The calculator uses the full-month storage allowances, two MAUs, 64 invokes with initialization headroom, one million read/write units each, 100 secret/S3/Scheduler operations and the USD 0.25 reserve. Convert each normalized decimal rate's workload contribution to integer microdollars, rounding upward, then sum with the fixed reserve. Exact rational arithmetic avoids floating-point threshold drift and supports scientific notation. No credits/free-tier assumption, caller-provided forecast override or hard AWS spending-cap claim.

Bind the complete normalized quote digest into the plan. Rates must be retrieved within 24 hours, never in the future, and the computed estimate must be at most USD 2. The next adapter must verify official source/region/units and retain private source provenance; a digest does not authenticate its origin.

Reserve USD 2 for each consumed run identity, at most two identities, plus a distinct USD 1 cleanup reserve: maximum envelope USD 5. A failed or uncertain create consumes its identity. A new run refuses duplicate identities, a third slot or any earlier run lacking verified cleanup. This PR only validates a ledger snapshot; atomic private reservation before the first AWS write, crash recovery and reconciliation are still issue 30 work.

## Verification and acceptance limits

Ten focused cases pass for identity/source/CI drift; missing/unknown/coerced fields; stale/future inputs; exact budget, quota, start/stop/cutoff and credential/refresh boundaries; all rate/source changes; duplicate/exhausted/unresolved slots; fixed private errors and immutable snapshots. The actual hosting/cleanup factories accept the normalized lease. The calculator reproduces the canonical USD 1.488729 model and tests the USD 2 boundary plus one microdollar, tiny scientific values and overflow. All 161 shared cases in 32 files, TypeScript, formatting, web build, five template-schema checks and actual Node 24 packaged checks pass locally. The existing browser chunk-size warning and Lambda ZIP/hash are unchanged. Hosted gates must pass before merge.

Passing these checks proves an offline policy contract. Actual observation collection, private journal durability, resource absence, audit configuration, quota/refresh acceptance, provisioning, scheduled sentinel deletion and full managed teardown remain unclaimed. Never use this validator as a substitute for those gates or as permission to enable the app's Cloud mode.
