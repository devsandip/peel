# Private Cloud identity observations

## Purpose and boundary

[Issue 45](https://github.com/devsandip/peel/issues/45) collects the narrow identity/session inputs for the [deployment-plan guard](cloud-deployment-guards.md), under [M2.2](https://github.com/devsandip/peel/milestone/2), SPEC FR-04/14/20 and AC-04/12/13 prerequisites. One PR handles this credential boundary. It does not provision, change credentials/configuration, invoke a login UI or establish complete account readiness. Source/artifact attestation, quota/audit inspection, ownership and lifecycle/apply remain separate issue 30 work; managed proof stays issue 31. Product v0.7 and app Cloud activation are unchanged.

## Independent expected identity

Require an explicit existing SSO profile, `us-east-1` and the authorization cutoff. First require scoped CLI history to be disabled/absent: AWS [documents that enabled history persists API requests/responses](https://docs.aws.amazon.com/cli/latest/userguide/data-protection.html), including sensitive material. Then read configured `sso_account_id` and `sso_role_name` before resolving credentials. These existing user-owned settings supply the expected identity; the STS result never populates that pin. Require unsupported credential-process, nested assume-role and web-identity settings to be absent before authentication. Refuse missing/ambiguous configuration without creating profiles or directly editing caches. Normal existing CLI credential resolution may refresh its own cached authentication.

Call only regional STS GetCallerIdentity, with an explicit `https://sts.us-east-1.amazonaws.com` endpoint and a fixed query for Account/Arn. Compare account and the AWSReservedSSO role name/suffix with the independent configured account/permission-set name. Session names and raw ARNs never leave process memory. Record only the expected and matched normalized identity in a private observation.

CLI operations use argument arrays without a shell, fixed read-only command kinds, disabled pager/prompt/color, bounded buffers/timeouts and no debug flag or retry. Ignore configured endpoint URLs in the child and reject environment credential/config/endpoint overrides; [explicit endpoints and the ignore setting](https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-endpoints.html) prevent metadata from silently using a local or alternate service. Preserve the user's files and global environment.

## Credential expiry and honest runway

Resolve the same profile through `aws configure export-credentials --format process`, capturing stdout privately. AWS [documents that this command ignores query/output filters](https://docs.aws.amazon.com/cli/latest/reference/configure/export-credentials.html). Never rely on such a filter, print the raw response, hash it, attach it to errors or persist its keys/token. Validate the version-1 [process schema](https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-sourcing-external.html), extract UTC expiry and discard credential fields. Normalize UTC seconds/milliseconds/microseconds conservatively to milliseconds; missing or malformed expiry cannot establish temporary-session runway.

This slice reports direct session lifetime only. It sets `refreshProven: false` and `refreshExpiresAt: null`; a configured SSO session does not prove an absolute refresh runway. [Modern and legacy SSO differ](https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-sso.html), and OAuth client registration expiry or token presence cannot substitute for usable login lifetime. Do not force refresh by editing caches or fabricate a two-hour credential window.

Observe both a matched identity and usable current session before reporting readiness. Project a full 90-minute run plus 30-minute cleanup from completion, and require both direct credentials and the explicit authorization to cover it. Insufficient runway is a valid not-ready observation and blocks creation. The actual plan guard must recheck against its exact lease before any write; this observation is not a reservation or permission to deploy.

The history guard runs first, five configuration reads may then run concurrently, and STS/credential resolution follow sequentially. Each subprocess has a 15-second timeout/64-KiB output bound; the entire collector has a 45-second abort deadline. Capture the oldest observation time and reject clock reversal/overrun. Fixed failure codes distinguish configuration, identity, credential and timeout problems without reflecting raw command output or rejected values. A history-enabled profile stops before account identity or credential export; the tool never changes that setting.

## Output and acceptance

Return a frozen normalized private snapshot with configured identity, matched identity, expiry and safe readiness facts. Public-facing summaries contain only fixed codes/booleans and zero resource writes. A read-only command accepts only profile/cutoff, writes any normalized identity/expiry snapshot to a new ignored mode-0600 file inside a private directory, and never overwrites earlier observations. Unavailable results contain no partial identity, credential fields or raw error causes. No note or default database is accessed.

Ten focused cases pass for independent pin/role/account drift, history/unsupported flows/overrides, exact command scope, credential-output redaction, malformed/expired/insufficient lifetime, fixed errors, timeout/abort and immutable snapshots. All 186 shared cases in 35 files, TypeScript, formatting, web build, five provider-schema templates and actual Node 24 packaged checks pass locally. The focused cases also pass under actual Node 24. The Lambda ZIP/hash and existing browser warning are unchanged; hosted gates must pass before merge.

No refresh claim was made. The normalized output is ignored, with file mode 0600/directory mode 0700; a local check confirmed no raw ARN, user ID, key or token fields. Only safe readiness booleans were printed. This does not establish later runway, quota/audit/source readiness or permission to provision. Recheck the exact lease before a write. No resource was created and no managed acceptance is claimed.
