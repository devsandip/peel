# Connect editing to server confirmation

[Issue162](https://github.com/devsandip/peel/issues/162) connects the existing [capture/session](cloud-new-note-capture.md) and [editor](cloud-note-editor.md) to an actual mutation sender. This plan precedes code. [SPEC](../SPEC.md) FR-02/04/08/11/13/14 and AC-02/04/09/12/13/20 remain the contract. This slice connects the existing components into a working save-and-read path while preserving the planning, review and validation approach Sandip reaffirmed.

## One working slice

Add a scoped upload owner that constructs its own draft session and durable client from the same captured scope/store. Accept an explicitly authenticated sender and an account-context AbortSignal; neither cache scope nor a client flag grants authentication/entitlement. Retain before preparing, reuse immutable in-flight requests after lost responses, validate status/receipt/scope before dispatch, and refresh the original session only from the durable result. Older receipts cannot save newer typing. Coalesce requested uploads while one is active, and stop automatic draining on authentication/network/conflict/local failure. No automatic failed-request retry or account retargeting.

Cancellation prevents queued sends and late responses from starting acknowledgement writes. Guard local client commits too, so an abort during an acknowledgement read cannot start a subsequent commit. An already-started local transaction may finish in its original scoped store; it cannot be recalled or redirected. Caller owns storage and authenticated context lifetime.

Wire this owner to the existing Markdown editor. Retention triggers upload; mount resumes a retained pending/in-flight operation. Put away still waits only for local retention and initiates upload without awaiting the network. Generic upload recovery may offer Retry; keep one normal titlebar control, original session/undo/dismissal guards and truthful Pending/Saved status. No default app activation, login shortcut or Local/native change.

## Confirmed autosave clarification

Sandip explicitly reaffirmed that every edit autosaves and there is no dedicated Save button. Keep immediate durable local draft retention. Batch automatic Cloud requests in fixed200ms windows starting with the first retained edit, without resetting that window on each keystroke, so continuous typing cannot postpone upload indefinitely. Successful queued work gets another bounded window; authentication/network/conflict failure pauses automatic scheduling until explicit retry or an authenticated reconnect trigger. Put away flushes the scheduled upload attempt immediately but never waits for its response. Account abort removes any scheduled timer. Retry remains an error-recovery control, not a normal Save action.

Keep generic upload recovery inside the existing note body, preserving the independent paper note and its sole titlebar control. Verify the window/debounce behavior with controlled timers and the actual HTTP/browser flows. This amendment precedes the batching implementation; the existing first source review/gates do not cover the changed head.
