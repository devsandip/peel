# Bounded peer inventory and delivery enumeration

## Requirements and plan

FR-13/14/17/19, AC-04/09/10/12/21/25. The current store requires callers to know note IDs and the channel fixture chooses packets manually. Add a local enumeration prerequisite before a production reconnect scheduler; do not enable app sync or repeat stopped relay/native experiments.

1. Add bounded metadata scans on both adapters for committed heads, permanent purge markers and pending delivery references. Return IDs, generations and recognized ordering metadata only. Never enumerate note projections, unstamped draft bodies, recovery history, keys or session proofs. SQLite should project head metadata before crossing its binding; IndexedDB may read one stored head at a time to project it, so do not claim zero content reads there.
2. Scope typed cursors to library/device, scan phase, version and a consistent inventory generation. Reject unknown, stale and cross-library cursors without reporting a truncated pass as complete. Use an inventory generation that changes with heads/purges, so unrelated receipt/trust writes do not continually restart a pass. Protect the new semantics from older experiment writers and establish explicit upgrade behavior. Local capture never waits for an inventory pass.
3. Enumerate one peer's pending references without exposing other target lists. Resolve one matching generation from committed head/purge/pending records only, avoiding note history and newer unstamped source. A changed generation returns a retry outcome; third-party forwarding requires missing author proof and must remain refused. No local acknowledgement or queue clearing from an inventory hint.
4. Exercise real SQLite and IndexedDB with empty and multi-page corpora, bounded large-note projection, writes and purges between pages, unrelated receipt writes, stale/foreign cursors, coalesced generations, drafts, permanent tombstones, failure/reopen and direct-author refusal. Include legacy identity/counter initialization and concurrent writers.
5. Record measured outcomes separately from performance targets. Metadata enumeration is not a complete anti-entropy wire protocol, forwarding proof, reconnect scheduler, native migration or app sync. Production continuous-edit freshness and long-term seen/history bounds remain gates.

## Decisions and limits

Keep the existing normalized records as the source of truth and avoid another whole-library JSON snapshot. Reuse ordered primary-key ranges where possible. Inventory is a discovery hint; only a verified packet and durable transaction can change or acknowledge a note. Public mockups, app-wide storage modes and local capture remain unchanged.

Logical identity version 4 accepts versions 1/2/3 as upgrade inputs. The first enumeration can atomically commit an identity-only upgrade with zero-based inventory/delivery generations; existing normalized heads remain discoverable without a body rewrite or index backfill. Every current writer preserves those counters. Head/purge changes increment inventory generation; pending-reference changes increment delivery generation in the same compare-and-swap. Old experiment writers reject version 4. The generic table/IndexedDB layout stays version 1; the production app schema is untouched.

Pages default to 32 scanned records, cap at 64 and return at most 64 KiB of projected metadata. Target filtering still advances the cursor across unmatched rows. A head phase is followed by a purge phase; an empty page with a cursor is incomplete. Local continuation fields carry an HMAC-SHA-256 integrity check using one device-local random key, initialized only by enumeration. Forged phase/position/generation fields are rejected. A changed generation returns an explicit restart with no entries. Cursor completion describes a local snapshot pass and never means Synced. Pending pages use the separate delivery generation. SQLite projects JSON fields inside its query; IndexedDB projects one cursor value at a time. [SQLite JSON functions](https://www.sqlite.org/json1.html).

The continuation key is not a device-authentication key and supplies no remote authorization. A same-origin database reader can access it; peer trust remains a separate boundary. It is never included in metadata pages or reports. Missing/corrupt key state rejects continuation without replacing it; an explicit new pass can initialize a missing key. Local capture does not consult or create it.

Scoped APIs derive the delivery target from an active session handle and check current durable trust before and after a scan and before returning asynchronous results. Resolution reads one committed head/purge/pending tuple, without loading recovery history or an unstamped projection. A newer generation yields Changed; an author other than this device yields Author proof required without returning a packet. The direct-author forwarding gate remains in force.

## Evidence

Eleven shared inventory contract scenarios pass on actual SQLite 3.53.2 and Chrome 156 IndexedDB. They cover fresh/legacy identity upgrades and failed-upgrade rollback; 95 paged heads/purges with a 256 KiB source and an unpublished draft; source-free output; cursor stability through receipt/trust/draft/stale-edit changes; invalidation on published heads/purges; empty target-filtered progress and foreign/malformed cursors; generation-specific resolution without draft/history reads; unsigned forwarding refusal; failed acknowledgement/reopen; concurrent counters; exhaustion preserving local drafts; immutable async inputs; forged continuation rejection/concurrent initialization; and malformed/future identities. The current-trust contract adds an eleventh case for recipient binding and revocation during a held scan. All 75 shared cases, TypeScript and formatting pass. Eleven existing store scenarios, four SQLite SIGKILL boundaries and browser projection/draft reload remain passing. [Store metadata](../experiments/peer-inventory-2026-10-27.json).

The bound Chrome harness now passes 29 checks across twenty host/host DTLS sessions. A bounded local pending scan and one-generation resolver drive three outstanding deliveries through a fresh authenticated session without selecting their note IDs manually. The previous lost-receipt generation is deduplicated, and newly enumerated Archive/Trash notes retain exact source/state. This is local outbox discovery, not a network anti-entropy exchange or production reconnect scheduler. [Channel metadata](../experiments/bound-inventory-2026-10-27.json).
