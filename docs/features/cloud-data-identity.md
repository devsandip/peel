# Disposable Cloud data and identity infrastructure

## Requirement and PR boundary

[Issue 28](https://github.com/devsandip/peel/issues/28), in [M2.2](https://github.com/devsandip/peel/milestone/2), defines only the data/identity part of the [controlled hosting plan](cloud-dev-hosting.md). SPEC FR-04/14/20 and AC-04/12/13 remain product requirements. One purpose: render and validate disposable DynamoDB/Cognito infrastructure before the later private Lambda, cleanup and managed-evidence slices. No AWS account operation or resource creation belongs in this PR.

## Plan before implementation

1. Accept a canonical random UUID run identity; generate one deterministic CloudFormation template with owned names/tags and exact outputs. No actual account ID, credential, user/password, CloudFormation transform, parameter default, production resource or public data endpoint. Reject ambiguous/run-name injection; distinct runs must not reuse resource names.
2. Define one Standard/on-demand PK/SK string table, TTL attribute `ttl`, maximum read/write throughput of 20 units each, no indexes/streams/replicas/PITR/backups and no retention/deletion protection. AWS-owned encryption remains enabled without an extra KMS key. These tiny synthetic limits are operational protection, not a hard spending cap or a production sizing decision.
3. Define one Essentials pool with administrator-only creation, administrator-only recovery, MFA off, no email/phone/alias/auto-verification/analytics or external provider. Register a public client without a secret, code-only OAuth with `openid` and `peel-dev/sync`, short explicit token lifetimes and one exact reserved HTTPS callback. Explicit refresh-only SDK auth avoids omitted-flow defaults; it does not replace code/S256 sign-in. Actual synthetic user creation must later use SUPPRESS; none is created here.
4. Supply a prefix domain with managed-login version 2 and default Cognito branding. Order custom scope/client/domain/branding dependencies explicitly. Outputs must connect to the packaged runtime and private PKCE helper without accepting an owner or paid flag. No data service is exposed at that domain.
5. Validate against the AWS-maintained cfn-lint resource schemas, pinned to 1.58.0 with pinned isolated Python tooling dependencies. Rendering/linting requires no AWS credentials or network/account calls. Add a hosted schema check alongside the artifact job; never hide warnings by weakening the template check. Unit checks cover run isolation, no unsafe resources/configuration and the generated configuration connected to actual runtime parsing and PKCE behavior, rather than only snapshotting the implementation.
6. Run relevant type/format/shared/schema/artifact checks and web build; review and merge one focused PR after all hosted gates. IaC alone does not pass managed identity/IAM/cleanup, sign-in, app, live-delivery or public acceptance. Further provision/cleanup guards remain required before an actual create.

## Primary-source basis

AWS documents [on-demand maximum throughput](https://docs.aws.amazon.com/AWSCloudFormation/latest/TemplateReference/aws-properties-dynamodb-table-ondemandthroughput.html) and [AWS-owned encryption when SSEEnabled is false/omitted](https://docs.aws.amazon.com/AWSCloudFormation/latest/TemplateReference/aws-properties-dynamodb-table-ssespecification.html). The latter still encrypts at rest; true instead selects AWS-managed KMS and incurs its charges. See [pool settings](https://docs.aws.amazon.com/AWSCloudFormation/latest/TemplateReference/aws-resource-cognito-userpool.html), [client/code/scope and SDK auth defaults](https://docs.aws.amazon.com/AWSCloudFormation/latest/TemplateReference/aws-resource-cognito-userpoolclient.html), [recovery options](https://docs.aws.amazon.com/AWSCloudFormation/latest/TemplateReference/aws-properties-cognito-userpool-recoveryoption.html), [domain version](https://docs.aws.amazon.com/AWSCloudFormation/latest/TemplateReference/aws-resource-cognito-userpooldomain.html) and [default branding](https://docs.aws.amazon.com/AWSCloudFormation/latest/TemplateReference/aws-resource-cognito-managedloginbranding.html). [cfn-lint](https://github.com/aws-cloudformation/cfn-lint) checks resource-provider schemas locally; this is not a deployment or IAM simulation.

## Evidence and remaining gates

The six-resource deterministic template renders under Node 24 and 26. Three focused shared cases pass: strict run-name handling/disjoint names; disposable capacity/encryption/identity/delivery policy; and generated outputs driving the actual runtime parser and private code/S256 initiator. No user, secret, role or data API is defined.

Pinned cfn-lint 1.58.0 validates the generated template against its us-east-1 resource schemas with no warning/error output. A deliberately invalid table-class control is rejected, confirming the schema gate runs. The explicit config applies no ignored checks; all nine Python validation packages are version-pinned in a separate virtual environment and the hosted artifact job installs them using pinned setup-python code. These are provider-schema checks, not a live API or IAM simulation.

All 142 shared cases in 29 files, TypeScript, formatting, Node 24 render, existing packaged Lambda checks and web build pass locally. The Lambda ZIP remains byte-for-byte unchanged at 336,713 bytes with SHA256 8603e9d37675877161f68d7e5a3b97b8cc57e247302a7dcbf690600671eb1013. The existing browser chunk-size warning remains. Hosted checks are pending and are recorded in the linked PR/issue when complete.

Access/ID tokens are configured for 15 minutes and refresh for 60 minutes; this is fixture configuration, not verified managed issuance or production refresh behavior. Admin-create suppression belongs to the later guarded fixture runner; no user-creation operation exists here. No managed identity, table, message, account or public API is created. Production email verification/reset, public API/static hosting, paid-policy administration, native/web sessions, secret/lease/IAM/cleanup and live sync remain separate work. Version 0.7 scope and mockups are unchanged.
