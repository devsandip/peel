# Bound original Cloud context storage

## Purpose and boundary

[Issue100](https://github.com/devsandip/peel/issues/100), under issue30/[M2.2](https://github.com/devsandip/peel/milestone/2), persists exact [original normalized context](cloud-run-plan-context.md) against actual existing [manifest](cloud-manifest-storage.md) and [reservation](cloud-run-reservation-binding.md) stores. It reuses the [immutable engine](cloud-immutable-record-engine.md) for SPEC FR-04/14/20 and AC-04/12/13 prerequisites in the [hosting plan](cloud-dev-hosting.md). Canonical v0.7/product behavior is unchanged. This is one immutable operator context boundary, not an appendable creation journal or execution permit.

## Contract and decisions

Require an explicit new context directory, exact context JSON and independently expected SHA256, original manifest directory/normalized pins and canonical ledger directory/original authority. Capture strict data-only nested fields, bounded digests/pins/authority and canonical absolute path strings before I/O; resolve existing parents once and retain detached frozen expected state. Fixed context.json/owner.json and a separate format1 marker bind these expected original sources and owned directory/context/marker inode identities. No caller-selected name/kind/codec/owned/approved option, default path, existing-store bootstrap or source-store mutation. Existing manifest/ledger formats and APIs stay unchanged.

Before publishing a new namespace, verify the exact context hash, inspect the actual selected manifest through CloudRunManifestStore.inspect, decode the original context and inspect the actual selected ledger through inspectCloudRunReservationBinding. Repeat actual source checks during publication readback and every open/read/inspect. The expected marker binds independently selected canonical source paths/pins; each source store separately checks its own persisted ownership/inode identity. Source selection is a trusted operator input; copied namespaces never grant another run. Do not pin a changing ledger snapshot, so the original context remains readable after a second reservation/cleanup receipt.

Use the engine's exclusive original-descriptor writes, private modes, exact entries, bounded strict UTF8/BOM preservation, pre/post identity checks, before/after checkpoints, context/owner/root/parent sync and complete readback before acknowledgement. Open issues a fresh acknowledgement for context descriptors only. Inspect/read issues no new context sync acknowledgement; source manifest inspection never substitutes for a recipe-store re-sync acknowledgement, and existing SQLite recovery effects remain the ledger's contract. Unknown/incomplete/corrupt/link/mode/source mismatches fail privately and preserve state; no fallback/reset/repair/chmod/delete.

Cross-store checks are observations, not one atomic transaction or authorization for a future AWS write. Return detached frozen original context and current reservation observations, with authority/ownership unproven. Recovery after expiry uses original codecs/stores without live clock, today's validators/factories/cost or provider calls. Later intent/execution code must recheck original records, current permissions/source/cost/lease and lifecycle gates. Physical power-loss, provider provenance, managed/teardown and app acceptance remain unproven; audit51/managed31/native72 stay stopped.
