# Verified local model cache experiment

## Requirements and plan

FR-06/08/14 and AC-06/14 require downloaded local inference to work without networking, while capture and word search stay available. The resident-worker experiment is insufficient evidence for a fresh offline worker. This feature remains isolated from the app until native/iPhone compatibility and memory budgets pass. Preserve the approved 0.7 mockups and production bundle.

1. Add a dedicated public-artifact IndexedDB cache, separate from every note/account database. Validate a bounded immutable manifest of paths, sizes and SHA-256 before opening an installation. Bind readiness to the exact manifest identity, including model/runtime versions. No note source, queries or credentials enter this store.
2. Serialize installation/removal with a browser Web Lock. Use a random staging generation, verify bounded downloads before storing, and atomically promote the complete set. A failed/cancelled/replaced installation cannot remove the previously ready set or publish incomplete readiness. Recover an abandoned staging generation only after obtaining the lock; do not use clocks to steal a live installation.
3. Reverify artifact hashes from durable storage before ready use and when serving each artifact. Runtime misses/corruption fail closed, with no network fallback. Removal invalidates later reads from existing handles. Do not make the public model installer a general URL/file cache.
4. Exercise actual Chrome IndexedDB and independent workers: complete install/reopen, interrupted/cancelled installation, integrity/oversize/quota failures, version replacement and concurrent installer serialization. Use small synthetic artifacts for destructive controls and the pinned public model only for actual inference.
5. After installation, create a fresh model worker with external and local artifact networking disabled. Use cache-backed model and WASM factory/binary loading from the pinned runtime API. Verify real embeddings and retrieval, not merely an in-memory cache hit. Worker bootstrap is separate from model availability; do not claim an offline app restart without the production shell integration.
6. Record scoped evidence, TypeScript and meaningful regression checks. Keep consent/download/pause UI, native adapters, incremental private vector persistence, memory acceptance and held-out dogfood questions open. No stopped relay/WebKit probe, new AWS resource or billing action.

## Decisions and limits

Web Locks supply cross-worker exclusion without leases tied to wall clocks. Unsupported Web Locks is an explicit unavailable result in this experiment, not permission to silently drop a platform requirement. Interrupted downloads restart after bounded cleanup; pause/resume UI and range requests are not claimed. Keep prior complete artifacts through failed updates. All destructive tests use newly named disposable databases and synthetic public bytes.

## Evidence

The first complete cache run passed lifecycle checks and fresh-worker offline retrieval. A subsequent complete run also closed/reopened the dedicated Chrome profile before inference. Its single-file worker bootstrap was 72,342,952 bytes, in addition to the 50,601,773 verified public model/runtime bytes. Preserve this baseline in the experiment report; it is not an acceptable assumed product download cost.

Before proceeding, evaluate the pinned ONNX package's `onnxruntime-web-use-extern-wasm` export condition. Its installed package metadata selects the external-WASM JavaScript entry instead of the bundler entry containing static WASM asset URLs. Keep the exact locked external runtime files and hash-verified cache; compare bootstrap bytes and repeat the same offline retrieval/lifecycle controls. Do not change the model, dataset, runtime version, inference provider or production build. This follows ONNX's [deployment guidance](https://onnxruntime.ai/docs/tutorials/web/deploy.html) to account for JavaScript, WebAssembly and model artifacts separately. If this build choice fails, preserve the evidence and keep the product model decision open.

The export condition worked with identical offline retrieval and reduced the worker bootstrap to 641,549 bytes. Apply it to the original isolated throughput/RSS runner as well, preserve its previous bundled report and measure the same workload again. Record worker start through first vector separately from time measured inside the worker, and retain the existing aggregate-RSS limitations. No product memory budget or platform acceptance follows merely from a smaller bundle.

### Implemented boundary and observed checks

`packages/meaning/src/model-cache.ts` contains an M0 public-artifact adapter restricted to dedicated `peel-m0-model-` databases. Its canonical manifest digest binds identity, exact paths, sizes and hashes, with a provisional 16-file/128 MiB total cap. These are experiment bounds, not public download quotas. Source URLs and credentials are not stored. The loader receives only a cloned allowed artifact descriptor and an abort signal.

Install/remove use an exclusive [Web Lock](https://developer.mozilla.org/en-US/docs/Web/API/LockManager/request). Each download is bounded to its locked length and checked before writing. The stored staging set is reverified before an atomic strict-durability transaction promotes readiness and removes the prior generation. Failure rolls back promotion and cleans the abandoned generation. A later lock holder reclaims a worker-terminated staging set. Clock expiry does not steal an active operation. A verified handle rechecks hashes and its active generation on reads; remove/replacement invalidates later reads. This does not promise recall of already loaded public model bytes or protection against all browser storage eviction/power-loss behavior.

[Initial evidence](../experiments/meaning-cache-initial-2026-10-27.json) records the first connection-reopen/worker checks. [Bundled baseline](../experiments/meaning-cache-bundled-2026-10-27.json) adds a closed/reopened dedicated Chrome profile. [Latest evidence](../experiments/meaning-cache-2026-10-27.json) uses the external-WASM export condition and retains exactly the same pinned model and frozen retrieval corpus:

- Eleven actual IndexedDB lifecycle cases pass: complete reopen, no-download reuse, path/version binding, oversized/corrupt/missing download refusal, cancellation during a pending stream and after a committed staged file, stored-stage readback before promotion, durable corruption/repair, atomic version replacement/reclamation, handle invalidation on removal and concurrent installer serialization/queued cancellation.
- A real independent worker was terminated after committing one staged artifact and blocking on the next. Its held Web Lock was observed; a fresh holder reclaimed that artifact and reused the prior complete set. This is process termination/recovery, not a simulated successful callback.
- Forced aborts of an actual artifact-write transaction and of atomic promotion both preserve the prior ready set. Chrome 156 reports `AbortError` for the former and `InvalidStateError` for the next operation after the latter abort. All tracked request/transaction rejections are consumed; zero page errors were observed.
- The dedicated Chrome profile was closed and reopened after storing all eight artifacts. Two fresh workers then initialized with the browser context offline, each reading eight verified cache artifacts with zero fallback fetches. Both retrieved the unchanged 29/30 expected notes in the top three. Worker construction through the first vector took 550.385 and 488.320 ms; all indexing/30 queries took 2,193.165 and 2,183.645 ms including worker startup. These are two observations, not p95 acceptance.
- Model/runtime bytes total 50,601,773. The latest single-file bootstrap is 641,638 bytes, including the added first-vector instrumentation, compared with 72,342,952 bytes in the bundled baseline. Installation from preverified loopback files took 212.050 ms in the latest report; this is not internet download speed.

The external-WASM export condition selects the pinned package's `ort.webgpu.min.mjs` instead of its bundler entry's static WASM imports. The model and explicit WASM files/hashes remain unchanged. Transformers.js [cache implementation](https://github.com/huggingface/transformers.js/blob/4.3.1/src/backends/utils/cacheWasm.js) loads the verified WASM binary and factory through the read-only custom cache. Runtime factory execution uses a blob module; the experiment preloads only the worker bootstrap before disabling networking. It does not preload a pipeline or retain one across the profile restart.

### Failed control and remaining gates

An initial 64 KiB DevTools quota override did not confirm `QuotaExceededError`; its fixture assertion stopped the run. No actual quota-failure result is claimed or repeated unchanged. The later forced transaction aborts prove rollback paths, not quota exhaustion. Earlier promotion-control assertions also needed to include Chrome's observed `InvalidStateError` after an intentional abort. [Control metadata](../experiments/meaning-cache-controls-2026-10-27.json) preserves these limits. Actual quota exhaustion and cleanup failure remain open.

The isolated page has no production CSP. It uses blob worker/runtime modules, while the native app currently has `script-src 'self'`; that policy was not relaxed. Production shell/CSP loading, offline app restart, native/iPhone support, consent/download/pause UI, interrupted-download byte resume, model removal coordinated with active inference, private vector persistence/deletion and held-out dogfood quality remain open. Browser storage can be evicted. A public release still needs measured supported-device RAM budgets; the optimized throughput runner's aggregate RSS is not unique model allocation. TypeScript, formatting and 81 shared unit cases pass; no inference/cache code enters the production app.
